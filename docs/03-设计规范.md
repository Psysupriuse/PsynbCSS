# 校园活动管理系统 V1.0 设计规范

## 1. 主题配色（蓝色系校园风）

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色 | `#1677ff` | 导航栏、主要按钮、卡片标题栏、链接、选中态 |
| 辅助浅蓝 | `#e8f3ff` | 卡片背景、板块底色、hover 背景 |
| 文字主色 | `#222222` | 标题、正文 |
| 文字次要 | `#666666` | 辅助说明、时间地点等次要信息 |
| 成功绿 | `#00b42a` | 成功提示、报名成功状态 |
| 警告橙 | `#ff7d00` | 警告提示、"已结束"状态 |
| 危险红 | `#f53f3f` | 危险提示、删除按钮、错误信息 |
| 页面背景 | `#f7f9fc` | 全局背景，白色卡片浮于其上 |

## 2. 整体风格

- 简约校园 Web，卡片式布局；
- 圆角卡片（约 8px），轻量阴影，无花哨动画；
- 学生前台：顶部全局导航栏；教师后台：左侧菜单 + 右侧内容；
- 响应式适配电脑浏览器（以 1200px 左右宽为准，窄屏卡片换行即可，不做移动端专项优化）；
- 全局仅一个样式文件 `public/css/style.css`，类名 kebab-case（如 `.activity-card`、`.btn-primary`）。

### 2.1 登录/注册页特例（用户指定风格）

登录、注册两个入口页面不采用普通白卡，使用用户指定的视觉方案：

- **磨砂玻璃卡片**：半透明白（`rgba(255,255,255,0.55)`）+ `backdrop-filter: blur(14px)` + 白色细描边；不支持 backdrop-filter 的浏览器回退为 92% 不透明白；
- **Q 版校园背景**：手绘 SVG 插画 `public/images/campus-bg.svg`（教学楼钟楼、校门、树木、Q 版学生等，蓝色系），`cover` 铺满、底部对齐；
- **校名展示**：卡片顶部主标题"华东交通大学"+ 副题"校园活动管理系统"；
- 无动画装饰，延续全局"无花哨动画"约束；
- 其余页面维持第 2 节简约蓝色风格不变。

## 3. 组件规范

### 3.1 导航栏（学生前台顶部）

- 背景主色 `#1677ff`，白字；左：系统名"校园活动管理系统"；右：菜单项（首页 / 我的报名 / 个人中心 / 退出登录），当前页高亮（白字 + 半透明白底）。

### 3.2 侧边菜单（教师后台）

- 左侧固定宽（约 220px）菜单栏，白底，主色选中态；菜单项：后台首页 / 活动管理 / 个人中心 / 退出登录。

### 3.3 活动卡片

- 白底圆角卡片，顶部标题栏可用浅蓝 `#e8f3ff` 底 + 主色标题文字；
- 卡片信息区：时间、地点、主办方、简介（简介超出 2 行省略）；
- 操作按钮："查看详情"（主色按钮）。

### 3.4 按钮

- 主按钮：主色底白字；次按钮：白底主色描边；危险按钮：危险红；
- hover 状态加深 10% 即可，无过渡动画依赖。

### 3.5 状态标签（badge）

| 状态 | 颜色 |
|---|---|
| 未开始（可报名） | 成功绿 |
| 已结束 | 警告橙 |
| 已满员 | 危险红 |

### 3.6 提示条（flash message）

- 成功：浅绿底 + 成功绿文字；错误：浅红底 + 危险红文字；显示在页面内容顶部，可关闭。

### 3.7 表单

- 输入框：白底、1px 灰描边、圆角，聚焦时描边变主色；
- 必填项加 `*` 红标；校验错误在提交后于表单顶部提示条统一展示。

## 4. 命名规范

### 4.1 路由与文件

| 资源 | 命名规则 | 示例 |
|---|---|---|
| 学生端路由 | `/student/...` | `/student/activities/:id` |
| 教师端路由 | `/teacher/...` | `/teacher/activities/new` |
| 视图文件 | 功能名.ejs，按端分目录 | `views/student/detail.ejs` |
| 路由模块 | 端点名.js | `routes/teacher.js` |

### 4.2 数据库

- 表名复数名词；字段 snake_case；主键 `id`；时间字段 `created_at`；
- 外键命名 `表名单数_id`（如 `teacher_id`、`activity_id`）。

## 5. 代码规范

- JavaScript：2 空格缩进、分号结尾、单引号；
- 注释用中文，说明"为什么"而非"是什么"；
- 一个文件一个职责：路由文件不写 SQL，SQL 集中在路由内通过 `db.prepare` 参数化执行；
- 错误处理：所有路由的异常统一交给 Express 错误处理中间件（500 页），不裸露堆栈；
- 所有用户输入均服务端校验，前端校验仅作体验优化。

## 6. 时间与日期约定

- 活动时间格式：`YYYY-MM-DD HH:MM`（24 小时制），页面展示与数据库存储统一；
- "未开始/已结束"判定以服务器当前时间为准（`new Date()`），活动时间等于或早于当前时间即"已结束"。
