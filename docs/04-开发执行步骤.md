# 校园活动管理系统 V1.0 开发执行步骤

> 执行规则：**每完成一步 → git commit → 尝试 git push**。提交历史必须反映系统逐步形成的过程，禁止全部写完一次性上传。

## 0. 通用执行规则

1. 每一步完成后先本地自测通过（页面能打开、流程能走通）再 commit；
2. 提交信息格式：`步骤N: 做了什么`（如 `步骤3: 实现注册登录业务逻辑，区分角色`）；
3. 每步尝试 `git push origin main`；若网络不通（本机当前无法直连 GitHub），保留 commit，待网络恢复后补推，并在 devlog 记录；
4. AI 生成代码需人工校验后才 commit；
5. 每天工作结束更新 `devlog/YYYY-MM-DD.md`（完成事项 + 待办事项）；
6. 密码、密钥等敏感信息一律不进仓库（`.gitignore` 排除 `data/`、`node_modules/`、`.env`）。

## 2. 各步骤详细任务

### 步骤 1：初始化项目
- [ ] `git init`，创建 `.gitignore`（node_modules/、data/、.env）
- [ ] `npm init` + 安装 express、ejs、express-session
- [ ] 创建目录骨架（routes/、views/、public/、test/、data/、devlog/、docs/）
- [ ] 编写 README.md（项目介绍、启动方式、技术栈）
- [ ] 放入 docs/ 四份标准文档（本文件即其一）
- [ ] 配置远程仓库 `https://github.com/Psysupriuse/PsynbCSS.git`
- [ ] 空壳 app.js 能启动、访问 `/` 返回占位页
- [ ] commit + push

### 步骤 2：注册登录页面 UI
- [ ] `public/css/style.css`：按 docs/03 配色规范完成全局样式（导航、卡片、按钮、表单、提示条、badge）
- [ ] `views/login.ejs`、`views/register.ejs`：按需求文档 4.1 的内容
- [ ] 页面在浏览器可打开（未接后端，纯静态展示）
- [ ] commit + push

### 步骤 3：注册登录业务
- [ ] `db.js`：建 users 表；`data/` 自动创建
- [ ] `auth.js`：注册（校验用户名唯一、密码一致性、scrypt 哈希）、登录（校验 + 会话写入）、登出
- [ ] `middleware.js`：requireLogin / requireStudent / requireTeacher
- [ ] 登录后按角色跳转（学生 → /student，教师 → /teacher，先放占位页）
- [ ] 自测：注册两个角色账号、登录、错误密码提示、重复用户名提示
- [ ] commit + push

### 步骤 4：学生端列表与详情 UI
- [ ] `routes/student.js`：活动列表（卡片、标题/地点筛选）、详情页
- [ ] 数据来源：db.js 建 activities 表并写入演示种子数据（演示教师账号 + 3 条示例活动，README 说明演示账号密码）
- [ ] 详情页展示完整信息 + 报名按钮占位（步骤 7 接业务）
- [ ] commit + push

### 步骤 5：教师端后台框架
- [ ] `routes/teacher.js`：后台首页（统计占位）、活动管理列表页（空态）
- [ ] 侧边菜单布局（views/teacher/ 下 dashboard、activities）
- [ ] 新增/编辑活动表单页（activity-form.ejs，含全部字段与校验属性）
- [ ] commit + push

### 步骤 6：教师活动 CRUD
- [ ] `db.js` 增加 activities 表
- [ ] 新增活动（校验：标题/时间/地点/简介非空、时间格式、最大人数正整数）
- [ ] 编辑活动（仅本人活动，越权 403）
- [ ] 删除活动（POST + 前端确认，仅本人）
- [ ] 后台首页统计接入真实数据（总活动数、待开始/已结束数）
- [ ] 自测：教师建活动 → 学生端可见；编辑/删除同步生效；A 教师不能操作 B 教师活动
- [ ] commit + push

### 步骤 7：学生报名与我的报名
- [ ] `db.js` 增加 registrations 表（UNIQUE 防重复）
- [ ] 报名接口：三重校验（角色/未结束/未满员）+ 重复报名提示
- [ ] 详情页按钮状态：已报名（灰，不可点）/ 已满员 / 已结束 / 可报名
- [ ] 我的报名页：列表（活动名、时间、状态）+ 详情入口
- [ ] 自测：报名成功、重复报名被拒、满员被拒、已结束被拒
- [ ] commit + push

### 步骤 8：教师查看报名名单
- [ ] roster 页：活动信息 + 报名学生用户名列表（仅本人活动可看）
- [ ] 自测：报名前后名单变化；学生访问该 URL 返回 403
- [ ] commit + push

### 步骤 9：整体修复与验证
- [ ] 全流程回归：按附录 7 条验证点逐条执行并记录结果
- [ ] `test/smoke.js` 自动冒烟脚本，`npm run smoke` 一条命令跑通核心链路
- [ ] 修复回归中发现的 bug；页面细节统一检查（错别字、对齐、按钮状态）
- [ ] 更新 README（运行说明、账号说明、验证记录链接）
- [ ] commit + push（含补推此前因网络未推送的提交）

## 3. 运行方式

```bash
npm install        # 安装依赖（express、ejs、express-session）
npm start          # 启动服务，访问 http://localhost:3000
npm run smoke      # 运行冒烟验证脚本（需先启动服务）
```

## 4. 附录：软件验证要点（写入实验报告）

1. 注册学生账号、教师账号；登录确认跳转对应页面；
2. 教师新建活动，学生前台可以看到这个活动；
3. 学生对活动进行报名，不能重复报名；
4. 教师打开该活动，可以看到刚刚报名的学生名单；
5. 教师编辑/删除活动，观察学生端同步变化；
6. 权限校验：复制教师后台 URL，用学生账号登录访问，应当禁止进入教师页面；
7. 判断 V1.0 是否达成目标：核心业务流程全部可运行。
