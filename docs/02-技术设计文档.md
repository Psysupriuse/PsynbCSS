# 校园活动管理系统 V1.0 技术设计文档

> 状态：已获用户批准（2026-09-20）
> 关联文档：需求见 `docs/01-开发需求文档.md`，UI 规范见 `docs/03-设计规范.md`，执行步骤见 `docs/04-开发执行步骤.md`

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 运行环境 | Node.js v24.21.0（本机已装） | 本机无 Python/Java，Node 为唯一可用运行时 |
| Web 框架 | Express 4 | 最常用的 Node Web 框架，课设答辩易讲清 |
| 页面渲染 | EJS 服务端模板 | 无前端构建步骤，`npm start` 一条命令启动 |
| 数据库 | node:sqlite（Node 24 内置） | 零原生编译依赖，避免 Windows 上 better-sqlite3 编译问题；已实测可用 |
| 会话 | express-session | 登录状态保持，基于 Cookie |
| 密码存储 | crypto.scrypt（Node 内置）加盐哈希 | 不存储明文密码，满足 NFR-04，零额外依赖 |

依赖仅 3 个纯 JS 包：`express`、`ejs`、`express-session`。

## 4. 数据模型

### users（用户表）

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,        -- 用户名唯一
  password_hash TEXT NOT NULL,               -- scrypt 哈希（含盐），不存明文
  role          TEXT NOT NULL CHECK (role IN ('student','teacher')),
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

### activities（活动表）

```sql
CREATE TABLE activities (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  title            TEXT NOT NULL,
  time             TEXT NOT NULL,             -- 活动时间 'YYYY-MM-DD HH:MM'
  location         TEXT NOT NULL,
  description      TEXT NOT NULL,
  max_participants INTEGER NOT NULL,          -- 最大报名人数
  teacher_id       INTEGER NOT NULL REFERENCES users(id),  -- 主办教师
  created_at       TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

### registrations（报名表）

```sql
CREATE TABLE registrations (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  activity_id INTEGER NOT NULL REFERENCES activities(id),
  student_id  INTEGER NOT NULL REFERENCES users(id),
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE (activity_id, student_id)            -- 数据库层面防重复报名
);
```

**活动状态不落库**：查询时用 `活动时间 vs 当前时间` 计算"未开始/已结束"，避免状态不一致。

## 5. 路由与权限设计

### 公共路由（未登录可访问）

| 方法 | 路径 | 功能 |
|---|---|---|
| GET/POST | /register | 注册页 / 提交注册 |
| GET/POST | /login | 登录页 / 提交登录 |
| POST | /logout | 退出登录 |
| GET | / | 按登录状态与角色跳转 |

### 学生路由（requireLogin + requireStudent）

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | /student | 活动列表（卡片式，可按标题/地点筛选） |
| GET | /student/activities/:id | 活动详情 |
| POST | /student/activities/:id/register | 报名（FR-07 校验见第 6 节） |
| GET | /student/my | 我的报名记录 |
| GET/POST | /student/profile | 个人中心 / 修改密码 |

### 教师路由（requireLogin + requireTeacher）

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | /teacher | 后台首页（总活动数、待开始/已结束数） |
| GET | /teacher/activities | 活动管理列表（仅本人活动） |
| GET/POST | /teacher/activities/new | 新增活动 |
| GET/POST | /teacher/activities/:id/edit | 编辑活动 |
| POST | /teacher/activities/:id/delete | 删除活动 |
| GET | /teacher/activities/:id/roster | 报名名单 |
| GET/POST | /teacher/profile | 个人中心 / 修改密码 |

## 6. 权限校验设计

- `requireLogin`：未登录访问任何受保护页面 → 重定向 /login；
- `requireStudent` / `requireTeacher`：登录但角色不符 → 403 页面（对应验证点 6）；
- **越权防护**：教师对活动的编辑/删除/查看名单操作，服务端校验 `activity.teacher_id === 当前登录教师 id`，否则 403（NFR-01"不同教师只能管理自己发布的活动"）；
- **报名校验**（FR-07，共 4 项）：
  1. 当前用户角色为 student（中间件保证）；
  2. 活动时间 > 当前时间（已结束不可报名）；
  3. 当前报名人数 < max_participants（满员不可报名）；
  4. 未重复报名：先查询 + `UNIQUE(activity_id, student_id)` 数据库约束兜底。

## 7. 安全设计

1. 密码使用 `crypto.scrypt` + 随机盐哈希后入库，任何页面不回显密码；
2. 会话密钥 `SESSION_SECRET` 从环境变量读取，无环境变量时随机生成（重启后需重新登录）；
3. 所有 SQL 使用参数化预编译语句（`db.prepare`），无字符串拼接；
4. `data/`（数据库文件）加入 `.gitignore`，仓库不含任何数据文件与密钥；
5. 登录失败不提示"用户名不存在/密码错误"的区分信息，统一提示，避免用户名枚举。

## 8. 错误处理与用户提示

- 所有表单服务端校验（空标题、时间格式、最大人数为正整数等），前端校验仅作体验辅助；
- 操作结果通过 flash 提示条展示：报名成功 / 已报名不可重复 / 已结束 / 已满员 / 用户名已存在 / 密码错误 / 保存成功 / 删除成功等；
- 统一 404 / 403 / 500 错误页面，蓝色主题；
- 删除活动采用 POST + 前端 confirm 确认，删除后学生端立即不可见（FR-11）。
