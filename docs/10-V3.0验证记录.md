## 四、对原有功能的影响与当前局限

**影响**：

- `activities` 新增 `category` 字段（默认"其他"），教师发布/编辑活动必须选择类型；V2.0 已有活动通过迁移脚本设为"其他"，不影响展示与报名；
- 报名/候补/审核/递补的状态机与名额计算逻辑未改动，只在成功分支追加写消息；
- 学生端导航新增"消息"入口，未读时显示徽标。

**局限**（如实说明）：

1. **消息是结果快照，不是实时推送**。学生必须打开页面才能看到未读数，站内消息解决的是"结果可发现"，不解决"即时到达"。数据中学生 mobile 占 70.9%，若要做到真正即时需要外部推送通道（短信/邮件/小程序订阅消息），需要额外凭据，超出本轮范围；
2. **V3.0 效果没有用真实运行数据验证**。本轮验证是功能级冒烟（44 项断言）+ 页面渲染检查，没有在新系统上再采集一批运行数据来对比"候补结果查看率"等指标。原因：本轮改造刚完成，尚无真实用户使用；课程提供的 V2.0 数据是教学构造样本，不能当作 V3.0 的实测结果（README_学生必读.md 明确禁止这样做）；
3. **筛选维度有限**。只提供类型、开始时间（本周/周末/本月）、关键字与剩余名额排序；"活动时间与课程冲突"这类个性化冲突检测需要学生课程表数据，系统不掌握；
4. **防重复提交是前端防护**。`js-submitting` 禁用按钮能挡住连点，但不能替代服务端幂等；若客户端禁用 JS 或并发提交，仍靠 `registrations` 的部分唯一索引兜底（会返回"不可重复报名"提示）；
5. **消息不做单条已读与分页**。只提供"全部标为已读"，列表上限 100 条，超出部分不展示；
6. **教师端/管理员端未做移动端专项优化**。本轮只适配学生端四个页面（数据中学生是 mobile 访问主体）；教师后台表格在窄屏改为卡片堆叠，但未逐页细化。
