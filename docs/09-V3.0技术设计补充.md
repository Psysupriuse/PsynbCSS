# 校园活动管理系统 V3.0 技术设计补充

> 关联：V1.0 技术设计见 `docs/02-技术设计文档.md`，UI 规范见 `docs/03-设计规范.md`。
> 本文件只记录 V3.0 相对 V2.0 的设计调整，V2.0 及更早的结构不变。

## 1. 数据模型调整

### activities 表新增字段

```sql
category TEXT NOT NULL DEFAULT '其他'   -- 活动类型，教师发布时选择；存量数据迁移为「其他」
```

### 新增 messages 表（站内消息）

```sql
CREATE TABLE messages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER NOT NULL REFERENCES users(id),
  activity_id INTEGER,                              -- 关联活动；与具体活动无关时为空
  content     TEXT NOT NULL,
  is_read     INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_messages_user ON messages(user_id, is_read, id DESC);
```

说明：

- 消息与报名记录解耦。报名记录 `registrations.status` 仍是唯一事实来源，消息只是**结果变化的通知副本**，不参与名额计算与状态机；
- 不设外键级联删除：活动删除时其消息保留（内容为纯文本快照），避免学生消息页出现空洞；这是与 `registrations` 随活动删除不同的取舍，因为消息的价值在"记录曾发生过的结果变化"；
- 未读数查询走 `(user_id, is_read, id DESC)` 索引，导航每次请求都查一次，学生量级下无压力。

## 2. 消息写入点（与 V2.0 状态机的衔接）

| 触发场景 | 写入位置 | 消息内容 |
|---|---|---|
| 报名成功（普通活动） | `routes/student.js` register | 「{活动}」报名成功 |
| 报名成功（需审核活动） | 同上 | 「{活动}」已提交，等待老师确认 |
| 满员自动进入候补 | 同上 | 「{活动}」已满员，已进入候补名单 |
| 主动加入候补 | 同上 waitlist | 已加入「{活动}」候补名单 |
| 候补递补转正 | `promoteNext()`（student.js 与 teacher.js 各一份） | 「{活动}」已候补转正，报名成功 |
| 审核通过 / 未通过 | `routes/teacher.js` review | 「{活动}」已通过审核 / 未通过审核 |

`promoteNext()` 在两个路由模块中重复定义是 V2.0 遗留结构，V3.0 只在其中追加消息写入，不做重构（避免影响已验证的候补链路）。

## 3. 筛选与排序设计

学生列表页筛选条件全部下推 SQL，避免全量拉到内存再过滤：

- 关键字：`title LIKE ? OR location LIKE ?`（沿用 V2.0）
- 类型：`category = ?`（精确匹配，类型来自固定列表）
- 开始时间：`time >= ? AND time < ?`。`activities.time` 是 `YYYY-MM-DD HH:MM` 本地时间字符串，字典序与时间序一致，因此可与同格式边界字符串直接比较；边界由服务端用 `Date` 的本地时间分量生成，不受服务器时区设置影响
- 排序：默认 `time DESC`；`sort=slots` 时按 `(max_participants - registered_count) DESC, time ASC`，即剩余名额从多到少

时间口径：本周=周一 00:00 起 7 天；本月=自然月；周末=未来最近的周六 00:00 至下周一 00:00。

## 4. 报名结果反馈与防重复提交

- 前端：报名/候补/取消/退出候补表单加 `js-submitting` 类，`public/js/main.js` 在 submit 时禁用按钮并改文案为"提交中…"。纯前端防护，目的是挡住连点，不替代服务端校验；
- 服务端：原有校验（已结束/重复/满员/活动不存在）保留，仅把提示语写清原因，例如"该活动已满员，已进入候补名单，有人退出后将按顺序递补"、"该活动已结束，无法报名"；
- 数据依据：V2.0 运行数据中 126 次重复 apply（占 4.6%）与 19 条"结果不确定"类反馈。

## 5. 移动端适配

- 断点 768px，只改布局不改信息结构；
- 顶部导航纵向堆叠、卡片单列、侧边菜单移到内容上方；
- 表格改为卡片式堆叠：`<td data-label="列名">` 配合 `td::before { content: attr(data-label) }`，`thead` 隐藏；
- 数据依据：V2.0 运行数据中 mobile 访问占 70.9%，而 V2.0 设计规范明确"不做移动端专项优化"。

## 6. 验证方式调整

`test/smoke.js` 在 V2.0 的 33 项断言基础上扩展到 44 项，新增：

- 类型筛选命中/不命中、排序与时间筛选可用
- 报名/候补/递补产生站内消息，未读徽标与"全部已读"生效
- 详情页报名表单带防重复提交标记，`main.js` 含禁用逻辑
- 已结束活动报名被拒且提示说明原因
- 样式表含 768px 断点，我的报名表格带 `data-label`

对原有功能的影响：V1.0/V2.0 的 33 项断言全部保留并继续通过，无回归。
