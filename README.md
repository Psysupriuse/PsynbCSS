# 校园活动管理系统 V3.0

软件工程课程实验项目（基于用户访谈的需求演化实验）。Web 网站，蓝色系校园风格。

**解决的问题**：V1.0 实现活动发布、浏览、报名的基础业务闭环；V2.0 新增报名审核与状态可见、取消报名与候补自动递补、系统管理员角色；V3.0 基于对 V2.0 运行数据的分析，新增站内消息通知、活动筛选与排序、报名结果明确反馈与移动端适配。

## 技术栈

- Node.js v24（内置 node:sqlite 数据库、crypto.scrypt 密码哈希）
- Express 4 服务端渲染（EJS 模板）
- express-session 会话鉴权

## 角色

| 角色 | 权限 |
|---|---|
| 学生 | 浏览/筛选活动、查看详情、报名活动、查看我的报名、站内消息、个人中心 |
| 教师 | 发布/编辑/删除自己的活动、查看报名名单、后台统计、个人中心 |
| 管理员 | 查看全部活动（只读监督）、停用/恢复账号、个人中心 |

V2.0 新增：报名状态（待确认/已通过/未通过）、报名审核与参加条件、学生取消报名、候补与自动递补、系统管理员。

V3.0 新增：站内消息（报名/候补/递补/审核结果自动通知，导航显示未读数）、活动列表按类型与开始时间筛选及按剩余名额排序、报名提交防重复点击与明确的失败原因提示、学生端移动端适配。

## 快速开始

```bash
npm install   # 安装依赖
npm start     # 启动服务，浏览器访问 http://localhost:3000
npm run smoke # 冒烟验证（需先启动服务）
```

演示账号（首次启动自动写入种子数据）：

- 教师：`teacher_demo / demo123456`
- 管理员：`admin / admin123456`

## 目录结构

```
app.js            入口：中间件、路由挂载、启动
db.js            SQLite 初始化、建表、种子数据
auth.js          注册/登录/登出/改密码路由
middleware.js    登录与角色校验中间件
routes/          学生端（student.js）、教师端（teacher.js）、管理员端（admin.js）、消息（message.js）
utils/           密码哈希（password.js）、活动状态判定（activity-status.js）、站内消息（message.js）
views/           EJS 页面（student/ 学生端、teacher/ 教师端）
public/          静态资源（css/style.css 蓝色主题）
test/smoke.js    冒烟验证脚本（44 项断言）
analysis/          V3.0 运行数据分析脚本（analyze.py）
data/app.db      SQLite 数据文件（运行时生成，不入库）
devlog/          开发日志（每日记录）
docs/            标准文档（01需求/02技术设计/03设计规范/04执行步骤/05实现计划/06验证记录/07 V3.0数据分析/08 V3.0需求调整/09 V3.0技术设计补充）
```

## 开发规范

- 按 `docs/04-开发执行步骤.md` 的 9 步迭代计划开发，每步独立 commit，提交历史反映系统逐步形成过程（`git log` 可查看）
- V3.0 的需求来自对 V2.0 运行数据的分析：`docs/07-V3.0数据分析与问题发现.md`，调整内容见 `docs/08-V3.0需求调整文档.md`，复跑分析：`python analysis/analyze.py <数据目录>`
- UI 配色与组件规范见 `docs/03-设计规范.md`
- 需求见 `docs/01-开发需求文档.md`，技术设计见 `docs/02-技术设计文档.md`
- 软件验证结果（7 条验证点、冒烟脚本输出、Bug 记录）见 `docs/06-验证记录.md`
- AI 生成代码均经人工校验后提交
